# BrowserBox（浏览器多开工具）说明与规划

> 文档版本：2026-08-11  
> 产品形态：Windows 本地 Electron 桌面应用（当前约 V1.0）  
> 本文档回顾已落地能力、模块划分，以及后续开发方向。

---

## 1. 产品定位

**BrowserBox** 用于在一台 Windows 电脑上管理多套互相隔离的浏览器环境：每套环境独立 Profile（Cookie / 缓存互不共享），可绑定不同代理，通过官方 **Chrome for Testing（CfT）** 或本机 Google Chrome 启动。

核心链路：

```
环境启动
  → 若有代理：proxy-chain 在 127.0.0.1 开本地无认证 HTTP 桥
  → Chrome --user-data-dir=独立目录 --proxy-server=127.0.0.1:端口
  → 上游 HTTP / HTTPS / SOCKS4 / SOCKS5（含账号密码）由本地桥转发
```

这样避开 Chromium 对「命令行代理带账号密码 / SOCKS5 认证」的限制。

## 2. 技术栈与仓库结构

| 层级 | 技术 |
|------|------|
| 壳 | Electron 37 |
| 前端 | Vue 3 + TypeScript + Vite + Element Plus + Pinia + Vue Router |
| 主进程 | TypeScript（electron-vite） |
| 代理桥 | proxy-chain |
| 原生 Win32 | koffi（进程枚举、内存无关的窗口/图标/结束进程） |
| 打包 | electron-builder（NSIS，每机安装） |

主要目录：

```
BrowserBox/
├── src/main/           # Electron 主进程
│   ├── app/            # 数据目录引导
│   ├── browser/        # CfT 下载、快捷方式与任务栏
│   ├── config/         # 配置读写与密码加密
│   ├── environment/    # 环境生命周期
│   ├── ipc/            # IPC 注册
│   ├── proxy/          # 代理 CRUD / 测试 / 本地桥
│   ├── win32/          # 原生 Win32 封装
│   └── index.ts        # 入口：窗口、托盘、单实例、退出确认
├── src/preload/
├── src/renderer/       # Vue 界面
├── src/shared/         # 共享类型
├── resources/          # 图标、安装脚本
├── electron-builder.yml
└── docs/               # 本文档等
```

界面路由：首次 Setup → 环境管理 / 代理管理 / 浏览器管理 / 设置。

## 3. 已完成模块一览

### 3.1 数据与配置（`ConfigManager` / `dataDir`）

- 数据目录自动选择：优先安装目录下 `Data`，Program Files 等不可写时回退到 userData
- 仅在失败时进入「手动设置目录」页
- 配置 JSON 持久化：`settings` / `environments` / `proxies` / `groups` / `tags`
- 代理密码加密存储（不回传到渲染进程明文列表的常规路径）
- 设置项：默认浏览器、启动间隔、日志级别、关闭窗口动作（询问 / 退出 / 托盘）、地区语言同步、**指纹信息**（简单伪装 / 深度伪装 / 关闭）、已删除浏览器主版本列表等

### 3.2 代理（`ProxyManager` / `LocalProxyManager` / `ProxyTester`）

- 代理 CRUD、批量导入 / 导出 TXT、批量删除
- 类型：直连 / HTTP / HTTPS / SOCKS4 / SOCKS5
- 经本地桥测试出口 IP 与延迟；列表国旗与状态展示
- 每个运行中的环境对应一个本地桥端口；停止时回收

### 3.3 浏览器（`BrowserManager`）

- 下载指定主版本 / 最新稳定版 Chrome for Testing 到 `Data/Browser/<major>/`
- 检测并使用本机 Google Chrome（`system`）
- 设为默认；**删除 CfT**（本机 Chrome 与当前默认不可删；有环境在用会拦截）
- 删除后写入 `removedBrowserMajors`，避免安装包内置副本被再次自动灌回
- **当前安装包不再打包 CfT**（体积约百 MB 级）；需用户自行下载或用本机 Chrome
- **开发态**：不从工程目录灌入内置浏览器（`getBundledBrowsersRoot()` 返回 `null`），避免中文长路径下 `cpSync` 导致进程崩溃；日志中「无内置浏览器目录，跳过灌入」属预期

### 3.4 环境（`EnvironmentManager`）

- 创建 / 编辑 / 克隆 / 删除（含 Profile）
- 批量创建（数量、名称前缀、代理轮询、浏览器版本、浏览器语言、**随机浏览器指纹**开关）
- 单环境 / 批量创建时可开关「随机浏览器指纹」（默认开）；关则不生成档案、启动不自动补档
- 可按环境指定 **浏览器语言**（预设优先于「地区语言同步」；时区仍优先跟代理国家）
- **环境导入 / 导出（.box）**：zip 含配置 + Profile；导出可选附带完整代理（含密码）；导入发新 UUID，代理按类型+主机+端口+账号匹配或新建
- 批量启动（可配置启动间隔）、批量关闭、批量删除
- 启动状态：启动中 / 运行中 / 已停止 等；UI 与托盘联动
- **定位**：按 `user-data-dir` 找进程并置顶窗口
- 运行中列表供托盘展示；手动关浏览器后状态能正确变为停止

### 3.5 任务栏与快捷方式（`TaskbarShortcut`）

- 每环境 `.lnk` + AppUserModelID，便于任务栏分组
- 环境图标：蓝色底图 + 编号徽章；主程序图标与环境区分
- 可选 exe 图标补丁（目录可写时）；窗口图标短暂多次注入后停止（不再常驻 PowerShell）

### 3.6 原生进程层（`win32/native`）

- 用 koffi 替代周期性 PowerShell：枚举进程、读命令行、等待退出、定位窗口、注入图标、结束进程
- 显著减少托盘下「PowerShell / 终端」进程跳动与资源占用
- Chrome 自身多进程（约十余个/环境）属 Chromium 正常行为，不改变

### 3.7 应用壳（`index.ts`）

- 单实例锁：再次双击只唤起已有窗口，不新开主程序
- 系统托盘：显示主窗口、运行中环境定位、退出前确认并提示将关闭全部环境
- 关闭主窗口：可询问 / 直接退出关环境 / 最小化到托盘（设置可配）

### 3.8 UI 视图

| 视图 | 能力摘要 |
|------|----------|
| Setup | 数据目录就绪失败时的手动设置 |
| Environments | 环境表、批量操作、定位、状态、浏览器语言、指纹抽屉、**.box 导入导出** |
| Proxies | 代理管理、测试、导入导出 |
| Browser | CfT 下载、默认、删除 |
| Settings | 数据目录、默认浏览器、启动间隔、关闭行为、地区语言同步、**指纹信息**等 |

### 3.9 指纹与地区一致性（V1.1 / V1.1.x）

- 启动时按代理 `country` 写入 `--lang`、Preferences `accept_languages`，并经 CDP 覆盖时区/locale（可被环境「浏览器语言」覆盖语言侧）
- 设置项 `syncLocaleWithProxy`（默认开启）
- 设置 **指纹信息**（`fingerprintMode`）：
  | UI 名称 | 内部值 | 行为 |
  |---------| | -------- | ------ |
  | 简单伪装（默认） | `ua` | 启动参数 UA + 短时 Client Hints/时区后断开 CDP |
  | 深度伪装 | `cdp` | 常驻 CDP，注入硬件相关字段（易被检测站标自动化） |
  | 关闭 | `off` | 不应用伪装 |
- 创建时可开关「随机浏览器指纹」；开启时生成并持久化 `Environment.fingerprint`，并记录创建时模式快照 `fingerprintMode`（`ua`/`cdp`）
- 环境行「指纹」抽屉：显示 **简单 / 深度 / 没有使用**（按创建时是否开随机指纹 + 模式快照）；可对照伪装档案与采集结果；停止后可重新随机
- Chrome 151 上 `--load-extension` 已不可靠；深度模式依赖常驻 CDP，不用扩展替代
- **局限**：非定制内核；深度伪装与检测站「真实度」存在权衡。简单伪装一般更不易被标机器人

## 4. 开发与打包

```bash
cd BrowserBox
npm.cmd install
npm.cmd run dev          # 开发
npm.cmd run pack:win     # 编译并打 Windows 安装包
```

产物：`dist/浏览器多开工具-1.0.0-Setup.exe`  
注意：打包前请退出正在运行的「浏览器多开工具」，避免 `win-unpacked` 被占用。

使用流程（无内置 CfT 后）：

1. 安装并启动  
2. 「浏览器管理」下载 CfT，或确认本机 Chrome 并设为默认  
3. 「代理管理」添加/导入并测试  
4. 「设置」按需选择指纹信息（简单伪装 / 深度伪装 / 关闭）与地区语言同步  
5. 「环境管理」创建环境（可关「随机浏览器指纹」、可指定浏览器语言）、绑定代理、启动  
6. 行内「指纹」查看使用状态、伪装档案与采集结果

## 6. 后续开发方向（规划）

以下按优先级与依赖关系排列，可随产品目标裁剪。

### 6.1 **已落地（V1.1）— 地区语言/时区一致性 + 指纹只读采集**

- 按代理 `country` 同步 `--lang`、Accept-Language、CDP 时区/locale 覆盖
- 设置开关：`syncLocaleWithProxy`（默认开启）
- 指纹采集面板（UA、语言、时区、平台、屏幕、Canvas/WebGL 摘要）

### 6.1b **已落地（V1.1.x）— 指纹信息（简单 / 深度）**

- 创建时可开「随机浏览器指纹」并持久化 `Environment.fingerprint`；记录创建时 `fingerprintMode` 快照
- **简单伪装（默认）**：`--user-agent` + 短时 CDP（时区 / Client Hints），立即断开
- **深度伪装**：常驻 CDP 注入硬件相关字段（易被标自动化）
- 每环境可指定浏览器语言（`browserLang` / `localePresets`）
- 抽屉：使用状态（简单 / 深度 / 没有使用）+ 伪装档案 vs 实际采集；停止后可重新随机
- **不做**：定制 Chromium、字体列表、ClientRects、WebRTC、对抗全部高级检测

### 6.1c **已落地 — 开发态浏览器灌入跳过**

- `npm run dev` 下不复制工程内巨型 CfT，避免崩溃；列表轮询触发的「跳过灌入」日志可忽略

### 6.2 P1 — 体验与稳定性补强

- ~~环境导入 / 导出（配置 + Profile）~~ **已落地（.box）**
- 分组、标签在环境列表中的筛选与批量改绑
- 崩溃 / 异常退出后的环境状态恢复与僵尸进程清理
- 托盘资源摘要（合计内存、主程序 vs 浏览器拆分）
- 日志查看页、一键打开数据目录

### 6.2a **已落地 — 环境 .box 导入导出**

- 导出：勾选范围或全部；始终含 Profile；可选完整代理（含密码）；运行中环境需先关闭
- 导入：新 UUID / displayId / Profile；代理匹配本机或按包内信息新建
- 模块：`src/main/environment/EnvBoxPack.ts`；IPC `environment:exportBox` / `importBox`

### 6.3 P1 — 环境墙（Env Wall）

在程序主界面**上方或独立页**增加「环境墙」视图：

- **总览图**：每个环境一张卡片/缩略区（编号、名称、代理地区、运行状态）
- **运行中预览**（可选阶段）：窗口缩略图或占位图；点击定位 / 聚焦
- **快捷操作**：单启停、批量启停、筛选「仅运行中」
- 与现有表格视图并存：墙看全局，表做精细编辑

实现注意：缩略图若用 Win32 PrintWindow / Magnification，成本与权限需评估；可先做「状态卡片墙」。

### 6.4 P1 — 批量任务与自动化

在环境墙 / 环境管理之上增加「任务」能力：

| 能力 | 说明 |
|------|------|
| 任务模板 | 打开 URL、等待、刷新、执行脚本片段等 |
| 批量下发 | 选中 N 个环境同时或按间隔执行同一任务 |
| 调度 | 定时 / 手动触发；失败重试与结果汇总 |
| 执行通道 | 优先 **Chrome DevTools Protocol（CDP）** 或扩展消息；避免再堆 PowerShell |

建议独立模块：`TaskManager` + 任务历史存储，与 `EnvironmentManager` 解耦。

### 6.5 P2 — 真指纹隔离（可选远期）

| 档位 | 内容 | 风险 / 成本 |
|------|------|-------------|
| C. 真指纹隔离 | 定制 Chromium（类 SunBrowser）或成熟注入框架 | 高：编译链、更新、合规 |

与代理多开主线解耦，单独立项。轻量 CDP 伪装已落地，真内核仍属评估项。

### 6.6 P2 — 同步与协作（可选）

- 配置云同步 / 团队共享代理池（需账号体系）
- 操作审计日志

### 6.7 技术债与约束

- 继续坚持：**少起外部进程、主进程 Win32 / CDP 优先**
- 保持单实例与数据目录互斥，避免双开写坏配置
- CfT 仍由用户下载；若将来要「精简包 + 可选内核包」可做双通道安装器，而不是再把双内核打进主包
